# 换电脑接手荔枝

## 先确定接哪一份

交出工作时，用一句话告诉接手人：最新副本在哪台设备或哪个受控位置、所在分支、完整提交号、是否还有未提交的工作，以及 GitHub 对应分支核对结果。生产口令和私有文件通过负责人指定的私有方式交接。

在来源副本根目录依次运行下面四条命令。最后一条用实际分支替换 `main`，直接查询 GitHub。

```sh
git branch --show-current
git rev-parse HEAD
git status --short --untracked-files=all
git ls-remote --exit-code origin refs/heads/main
```

本机提交号与远端输出的提交号相同、工作区干净，才可用该远端分支交接已提交的项目内容。若分支名为空、提交号不同、远端分支缺失、查询失败或有未提交文件，先说明具体差异，保留来源副本。由负责人决定同步到 GitHub 或私下转移需要的版本及未提交工作。换机后在目标副本核对提交号；随行的未提交文件逐项核对内容。被 Git 忽略的签名材料和运行数据需要单独恢复。

## 新 AI 从哪里开始

把已核对的副本位置、分支、提交号和本轮任务发给接手人，请其先读 `AGENTS.md`、当前计划和进展，再运行接手自检。

新电脑安装 Git 和 Python 3.10+。以下为已确认从 GitHub 的 `main` 接手时的命令。若交接的是其他已同步分支，把克隆命令中的 `main` 换成该分支。先比对输出的提交号与交接记录，一致后再运行自检。

```sh
git clone --branch main https://github.com/z1807767180-pixel/Lychee.git
cd Lychee
git rev-parse HEAD
```

```sh
python tools/check_handoff.py
```

6.4.7 预期输出包含 `verified 147 files and all platform entries`。在 macOS、Linux 上如果命令叫 `python3`，使用该命令。自检只需本地源码，在临时目录工作。真实账号、付费 AI、云端数据库都不参与。

## 一次性迁出原安卓签名

当前 6.4.7 的原件为 `Lychee-release.p12` 和 `password.dpapi`。第二个文件只能由创建它的 Windows 用户配置解开。第一次导出需要该账号；完成后，新电脑只需要便携 P12 和独立口令。

1. 在原 Windows 用户下找到这两个文件所在的实际目录。打开本地终端，确认 `python --version` 和 `keytool -help` 可用（JDK 21 的 bin 目录加入 PATH）。
2. 在仓库根目录运行下面的命令。用真实目录替换示例；目标是仓库外、原文件夹外、由自己控制的私有备份位置。脚本只读取原件，并在终端隐藏输入新的备份口令。

   ```powershell
   python tools/android_signing_backup.py export "D:\原签名目录" "E:\私人备份\Lychee-Android.p12"
   ```

3. 将新口令存入自己的密码管理器。将 P12 存到换机后仍可访问的私有备份位置。无需向 AI 提供口令；不要把 P12 或口令放入公开仓库。
4. 在**另一台电脑或另一份系统用户配置**下载仓库，用 Python 和 JDK 21 校验这份备份（Windows、macOS、Linux 均可运行）。这里要输入的只有新口令。

   ```sh
   python tools/android_signing_backup.py verify "/path/to/Lychee-Android.p12"
   ```

脚本比对已发布 APK 的证书 SHA-256，并用私钥签署一次临时证书请求以确认实际能签名。成功会显示 `Verified the release certificate and private-key signing access.`。仅能复制文件或看到证书名称不代表恢复成功。新版本可在持有者本地使用 Android SDK 的 apksigner 和此 P12 签名。

## 原电脑何时能清理

完成跨设备签名验证后，把原日期目录的源码、成品和私有交接资料逐项与备份对照；同目录里的其他项目单独处理。仓库自检只证明公开代码可恢复，不代表原机全部文件都已归档，也不代表线上数据库已备份。
