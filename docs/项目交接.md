## 产品与当前任务

本批功能已上线，进入试用反馈阶段。通知、安装升级和转盘的结项依据见[阶段归档](../.planning/lychee/阶段归档/2026-11.md)，照记饮食后续跟进见[当前计划](../.planning/lychee/task_plan.md)。

从移动版 V6.3.3 的完整体验出发，把同一套功能、美术、字体和业务规则带到 Windows、Android、iOS。Windows 保留桌面习惯，包括宽窗侧栏、小窗底部导航和自由拖动缩放。三端使用同一个后端。当前使用入口为 Windows 程序、安卓 APK 和 iPhone 主屏幕网页。iOS 原生工程单独保留，等待签名与真机验收。

Windows v4.1.7 是独立保留的旧版。新客户端 6.4.x 可以相互升级。历史分发位置出现过名为 6.4.0 或 6.4.6、内容已原位换为 6.4.7 的 ZIP；版本判断应核对内部 EXE 的 FileVersion、SHA-256 和版本清单。

## 已确认的产品规则

- 使用者可以公开注册。园内资料仅对已加入的人可见，加入需要邀请码。园内普通成员也能修改本园名称、简介并更换邀请码。个人资料由本人管理。
- 原来三位用户仍可使用旧账号和原荔枝园。正式服务沿用原来的 Render 与 Turso/libSQL，没有新购月费磁盘。前端先显示本地启动画面，后台再连接服务。沿用已有生产数据库时须注意与旧客户端兼容。
- 同一条公告每个账号提醒一次，之后可主动查看。界面统一使用霞鹜 975 圆体。
- 已入园的注册用户共用账号级 AI 限额。按北京时间每天 20 次问答、10 次生图，跨端、跨园共用。海龟汤主持与文字辅助计入问答，头像和封面计入生图。新生图按相册是否确实保存结算，断线查询同一任务，确认无图退回。旧版通用失败缺少逐图凭据，个别旧扣额无法追溯。
- 「荔枝园」有园中事、问一问、约定倒计时。「工具箱」的提醒事项、约定倒计时、问一问、番茄钟和记账本均为卡片。「我」放个人资料、头像和主题、通知与设置；版本信息在设置中。

## 可以依赖的验收结果

Windows 6.4.7 的朋友分发 ZIP 的 SHA-256 为 `edfe0b2c47cbd0729066e3aee9f0b688177edab1b6326a6263a06fc0471f1f4e`，内部 EXE 为 `635375f965bcb027a03703c04b9b16f94aa41570bd7a9b4df65d5603df28581e`。ZIP 校验通过，MSI 内封装的 EXE 已逐字节核对。真实 Windows 宿主上八个方向均命中系统缩放边缘并改变预期尺寸。用测试账号在桌面和手机尺寸页面验证了账目读写与番茄钟暂停、继续；手机尺寸页面测试与 Android/iPhone 真机验证分别记录。

线上验证过注册、邀请、成员编辑、公告已读、旧账号迁移，以及专用测试园的三类 AI 请求。生图新逻辑已通过断线、重试、退款、相册分片和重启测试；部署后用先前真实生成的图片只读验证过相册与额度。例行回归用本地模拟供应商即可。任何新的付费验收、生产部署、真实用户数据操作须按当次授权执行。

## 下一版从哪里开始

1. 从最新 `main` 开开发分支。先改共享功能，再检查 Windows、手机网页和原生壳上受影响的交互；从[源码说明](../source/接手说明.md)定位工程。
2. 各端按实际目标分别交付。网页沿用原网址和 `web/mobile-stable`。获准发布后，核对 Render 是否已经部署新提交。若未排队，手动部署该分支最新提交，再从原网址读回版本和资源。Windows 重建 EXE/MSI，安卓提高版本号并用同一私钥签名，iOS 原生单独决定签名和分发时间。准备新版本时核对对应发布脚本和输入摘要。
3. 在本表记录各端版本、成品链接、实测结果和缺口，并同步首页的用户入口。保留旧发布标签、工件和校验值。后端环境与数据库由部署方管理，安卓更新私钥由项目负责人单独保管。

## 工作方式

项目负责人使用中文，希望先看结论和可直接打开的成品。他要求 Router 负责整合，Worker 可并行开发和验收。变更按原方案核对，后续明确的需求以本交接记录为准。仓库公开用于交接代码、设计、版本和验证材料。生产服务继续独立管理；新会话从仓库读取源码并不会自动获得生产密钥、个人资料、聊天记录或签名权限。
