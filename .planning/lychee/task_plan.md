# 荔枝当前计划

## 大更新 · 统一账号首页、好友与群聊

负责人已授权整批开发、实测、三端正式发布和 GitHub 同步。负责人已采用 B 版个人首页，保留个人约定小卡，群聊和私聊在唯一的最近消息列表中混排并标类型，未发消息的群也能打开。移除原稿的常用群聊区。按下列小阶段跟踪，首页、荔圈、荔枝园及工具的入口和文案都要让人一眼看懂。阶段完成后，在[当前进展](progress.md)追加实际结果、证据和未验范围。

| 小阶段 | 怎样验收 |
| --- | --- |
| 1. 统一首页与个人约定 | 同一账号无论加入几个群，打开荔枝都回到同一个人首页，只看本人的个人约定。进群、返回首页、再进另一群，首页和个人约定保持一致。旧资料保留原处，沿可靠的账号关系读取原有内容，归属不明的记录保留原样。 |
| 2. 原有圈子变为群聊入口 | 在荔圈能找到并进入原来加入的群，认得同一张固定群封面。一个账号可以创建多个群，从好友列表分别邀请不同好友加入相应的群。打开不同群和返回列表均无需重新看应用启动页。进群能看该群成员，能从成员列表申请加好友。 |
| 3. 好友和私聊 | 两人同群就能在群里交流。双方确认好友关系后可单独私聊；仅同群者不会自动成为好友。一个人退出群后仍保有已加的好友、可继续私聊，退出的群按成员权限处理。 |
| 4. 荔枝园的好友内容 | 「园中事」和「问一问」新发布的内容由本人及其好友查看。旧帖保留在原处，沿用各自原有的可见范围。分别使用好友、仅同群者和无关系者核对新旧内容的列表、详情及互动入口。 |
| 5. 未读与回复提醒 | 荔圈内，群聊与私聊分别显示各自未读。荔枝园底栏汇总园中事和问一问的未读，例如各 1 条时底栏显示 2；看完其中一处，底栏剩 1，另一处仍提示，全部看完归零。能分辨直接回复自己的消息与一般新动态，可直接找到相应回复。 |
| 6. 每人一棵树 | 同一账号跨群看到自己的同一棵荔枝树，不同账号各有自己的树。好友可互赠荔枝，收发双方看到正确记录；仅同群不会解锁好友赠送。原群树、果实和旧赠送历史留在原处，无需搬动。 |
| 7. 聊天时间与界面 | 群聊和私聊均有居中的分段时间，连续消息不重复显示，跨日看得出日期。“相隔 5 分钟另起时间”是建议，具体间隔待定。以日常消息、长时间停顿、跨日三种对话核对，小屏和桌面都要读得清楚。 |
| 8. 两项现有故障 | 分别验收老安卓白屏和手机网页「交给命运」上方破图。安卓从原应用冷开到可操作页面，记录所测系统和 WebView；手机网页从原网址实际进入转盘，看上方图片正常显示并确认转盘仍可使用。各自记录复现条件、修复结果及尚缺的真机反馈。 |
| 9. 三端入口与版本 | 从下一版起，Windows 用 W、安卓 APK 用 A、手机网页用 V。对应端的设置、公告、下载或打开入口、交接记录和实际产物相符，历史版本沿用原标记。分别从 Windows 成品、安卓安装包和手机网址走完主要操作，记录各端验到哪里。 |

整项完成后，先把各阶段实际结果、验收范围、证据入口写入[当月阶段归档](阶段归档/)，确认可追溯，再从当前计划和进展移除本项。从三端用户入口读回正式版本、核对签名或成品、记录旧资料与真机验收边界，最后同步 GitHub 主分支、各端正式分支及首页交接。发布遵循[项目管理规范](../../docs/项目管理规范.md)及当次授权。
